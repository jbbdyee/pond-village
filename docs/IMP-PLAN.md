## P0. 프로젝트 셋업
- `uv init`, 폴더 구조 생성, pytest 동작, `.gitignore`에 `runs/`
- Ollama 설치 + 모델 하나 받아서 OpenAI 호환 엔드포인트로 "hello" 호출

**완료 기준**: `uv run pytest` 통과, `uv run python -m pondvillage.llm --ping`이 로컬 모델 응답 출력
**설명 체크**: 왜 Ollama와 유료 API를 같은 클라이언트로 부를 수 있는가?

## P1. 월드 + 규칙 엔진 (LLM 없음)
- `world.py`, `rules.py`: 연못 재생, 어획 배분, 판매, 생활비, 파산, 붕괴
- `tests/test_rules.py`: 배분 비율, 재생 상한, 파산 3일, 붕괴 경계값

**완료 기준**: 규칙 테스트 전부 통과
**설명 체크**: 요청 합계가 재고보다 많을 때 어떻게 나누는가? 지속 가능한 총 어획량이 왜 50인가?

## P2. 스크립트 봇 + 러너 + 기준선
- `agents/scripted.py`: 탐욕 / 협력 / 랜덤 봇
- `runner.py`: 하루 페이즈 진행 (LLM 페이즈는 봇이 대신)
- 결과를 콘솔 표로 출력

**완료 기준**: 탐욕 봇 마을은 붕괴하고, 협력 봇 마을은 30일 유지된다
**설명 체크**: 왜 LLM보다 봇을 먼저 만들었는가? (규칙 검증 + 비교 기준선)

## P3. 로그 (SQLite)
- `logger.py`: SPEC 7장의 테이블 생성과 기록
- 봇 실행 결과가 DB에 남는지 확인

**완료 기준**: 실행 후 `runs/<run_id>.db`에서 days, agent_days 조회 가능

## P3.5 마을 미리보기 화면 (대시보드 v0)
- 게임풍 HTML 한 장(2026-11-15 Streamlit에서 변경, NOTES 참고): 실행 두 개를 골라 마을을 나란히 재생 → 날짜별 연못 재고, 어부별 돈·잡은 수, 비교 그래프
- `export.py`가 `runs/*.db`를 읽어 `dashboard/village.html` 틀에 넣고 `runs/village.html`을 만든다
- 봇 실행 결과만 쓰므로 LLM 비용 0원. 파일 하나라 휴대폰에서도 열 수 있다
- P7(대시보드 v1)은 이 화면을 넓혀서 만든다

**완료 기준**: 탐욕 봇 마을과 협력 봇 마을의 재고·돈 변화를 화면에서 비교할 수 있다

> 2026-11-15 방향 변경: 1단계가 "모델 마을"(같은 모델 / 섞인 / 한 명만 다른)로 바뀌어 P4 이후 순서를 고쳤다. 규칙 투표는 3단계 후보로 미뤘다. 이유는 NOTES 2026-11-15.

## P4. LLM 에이전트 — 어획만 (어부별 모델)
- `llm.py`: 호출, JSON 파싱(코드 상자 벗기기 포함), 재시도, `llm_calls` 기록, 비용 계산, 비용 상한. JSON 모드 켬
- `agents/llm_agent.py`: 아침 공지 + 상태 → `fish` / `inspect_pond`. **어부마다 자기 `model`로 부른다**
- 설정: 어부별 `model`(비우면 기본 모델), `persona_enabled`(기본 false = 이름만)
- 프롬프트는 `src/pondvillage/prompts/`에 파일로 분리
- 러너가 시작할 때 Ollama가 살아 있는지 먼저 확인 (WSL이 쉬면 꺼져 있음)

**완료 기준**: 로컬 모델로 같은 모델 마을(qwen2.5:7b × 5)과 섞인 마을(qwen2.5:7b + gemma3:4b)이 각각 5일 진행, 파싱 실패해도 크래시 없음
**설명 체크**: 파싱 실패 시 어떻게 처리하는가? 프롬프트에 무엇을 넣고 무엇을 뺐는가? 왜 성격 문구를 뺐는가?

## P5. 기억 + 일기
- `memory.py`: 최근 2일 원본 + 이전 요약
- 일기 페이즈: summary, beliefs, trust JSON

**완료 기준**: 10일 실행 시 프롬프트 토큰이 날짜에 비례해 계속 늘지 않는다 (로그로 확인)
**설명 체크**: 왜 전체 기억을 다 넣지 않는가?

## P6. 광장 대화
- `say` (전체 / 귓속말), 발언 순서 시드 섞기
- 귓속말은 받는 사람 기억에만 들어감

**완료 기준**: 대화 켜기/끄기를 설정으로 전환 가능 (1단계는 켬, 비교용으로 끈 마을)

## P7. 대시보드 v1
- 마을 화면(v0)을 넓힌다: 어부마다 모델 표시, 광장 말풍선·귓속말, 대화 타임라인, 일기 보기 (참고 시안: 광장과 소문 장면)

**완료 기준**: 실행 하나를 대시보드에서 처음부터 끝까지 따라가며 읽을 수 있고, 누가 어떤 모델인지 보인다

## P8. 실험 러너 + 분석
- `configs/exp1_*.yaml`: 같은 모델 마을(S) / 섞인 마을(X) / 한 명만 다른 마을(O), 시드 일괄 실행 (`--paid` 없으면 로컬)
- 섞인 마을은 시드마다 이름 자리를 돌린다
- 분석 스크립트: EXPERIMENT 1단계 지표(모델별 평균 어획, 섞임 효과 포함) → 비교 표 + 그래프

**완료 기준**: 로컬 모델 2개로 S·X·O를 짧게(10일) 돌려 지표 표가 나온다

> 2026-11-17 정체성 정하기: 2단계를 "스스로 생긴 거짓"으로 바꿔 P8.5를 새로 넣고 P10을 "거짓 추적기"로 바꿨다. 이유는 NOTES 2026-11-17.

## P8.5 틀린 말 세기 (0원, 관문)
- `claims.py`(가칭): 광장 말에서 숫자 주장("어제 모두 15마리", "연못에 80마리")을 코드로 뽑아 그날 기록과 견준다. LLM 호출 없음
- 출처 찾기: 틀린 말을 한 어부의 그날 질문지(`llm_calls.prompt`)에 같은 숫자가 일기 요약으로 있었는지
- 이미 있는 기록(P4~P8, 대화 켠 실행)에 돌려 마을·모델별 표를 만든다. 사람이 직접 본 표본(예: 말 30개)과 견줘 판정기가 놓친 것을 적는다

**완료 기준**: 기존 기록에서 틀린 말 수·출처 비율 표가 나온다. **관문**: 틀린 말이 너무 드물면(대화 켠 마을당 1번도 안 됨) 2단계 방향을 다시 정한 뒤 P9로 간다
**설명 체크**: 왜 LLM 판정보다 코드 판정을 먼저 하는가? "기억에서 옴"이 증명하는 것과 증명하지 못하는 것은?
